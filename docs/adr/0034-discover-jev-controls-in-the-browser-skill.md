# Discover Jev controls in the browser skill

## Decision

Add an opt-in `scope.discover: true` mode to the shared Jev runner from
[ADR 0033](0033-skill-owned-jev-browser-runner.md). The caller supplies the
owned page, exact permitted origins, goal, ordinary field values, and any
independent completion checks. The skill code supplies provider and budget
defaults, discovers current low-impact controls, generates CSS selectors and
operation choices, binds values by exact field identity or label, executes
unambiguous bound values, derives immediate action effects, and repeats
discovery after every action. Keep the
existing explicit-control contract for tasks requiring specific authorization.

The discovered candidates are data passed to Jev or selected by deterministic
rules, not actions generated by Jev. Jev may select only a current
operation/control pair. The runner checks
origin, browser identity, node identity, descriptor, selector, and field state
again before dispatch. It never creates input values, broadens origin scope,
replays a click with an uncertain effect, or treats model `DONE` as proof.

## Rationale

The [frozen paired comparison](../research/jev-browser-integrations.md#why-our-current-integration-loses)
spent a median 19.62 seconds on parent-authored selectors, control lists,
effects, and checks. That exceeded the execution time saved by the inner Jev
loop. Repeated mechanical page preparation belongs in the harness-independent
skill code. Both Orca and agent-browser already expose the same normalized DOM
observation boundary, so dynamic discovery does not require a new browser or
agent-specific plugin.

The first discovery policy is deliberately narrow: current same-origin links,
ordinary text fields, checkboxes/radios, native selects, Filters disclosures,
and Next/Previous page buttons. It excludes form submit buttons, unknown
buttons, sensitive fields, downloads, and new-tab links. A label or DOM
attribute does not prove a control harmless; run this mode only on authorized
low-impact pages and retain explicit controls for other effects.

Caller-supplied strings are filled or selected deterministically. A supplied
`true` may check a matching checkbox/radio. If that target is still hidden,
exactly one visible Filters disclosure may be opened to reveal it. Other
choices remain Jev decisions; the confidence gate still applies to those.

## Consequences

For a generic task, code cannot derive a trustworthy final result solely from
the model's goal text. If no caller-supplied checks exist, `DONE` returns
`verification_required` for the parent or task-specific oracle. An observed
page change after a disclosure or pagination click confirms only that the page
changed, not that the goal was achieved. The caller still owns page/session
selection, value authorization, final semantic verification, and cleanup.

This mode is a new experimental candidate. The earlier failed comparison does
not measure it. Adoption requires the independent development and holdout
gates in the [follow-up plan](../plans/jev-deterministic-preparation-plan.md).
