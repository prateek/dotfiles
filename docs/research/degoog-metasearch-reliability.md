# Making Degoog and similar metasearch more reliable

The [local Degoog trial](search-index-fourth-run.md) had four distinct symptoms: Reddit RSS returned 429 for 26/27 core queries and all nine platform probes; DuckDuckGo returned results for only 5/27 core queries; Bing filled the result count with generic pages; and Startpage returned no results for four core queries. These counts are observations from one IP and one engine bundle, not evidence that a particular upstream permanently blocks every instance. Degoog is an aggregator whose server queries each enabled engine, so configuration changes cannot create a new index or make an upstream honor a query it ignores. [Degoog overview](https://degoog-org.github.io/docs/), [Degoog aggregation code](https://github.com/degoog-org/degoog/blob/5cd67cec74d38944792db498b604790624a1cbbe/src/server/search/scoring.ts)

## What upstream operators actually recommend

| Symptom | Evidence and supported response | Confidence and limit |
| --- | --- | --- |
| HTTP 429 from an upstream | Degoog's guide says slow requests, use caching, or use a proxy; its server docs also recommend keeping automatic retries low, because hammering a limited engine worsens the block. Use fewer default engines and a private instance so every agent search does not fan out unnecessarily. [Tips and tricks](https://degoog-org.github.io/docs/tips-and-tricks.html), [server settings](https://degoog-org.github.io/docs/server-settings.html) | Documented operational advice, not a guarantee that an already limited IP recovers. Degoog's inbound per-client limiter protects upstreams indirectly; it is distinct from an upstream 429. |
| Reddit 429 | The official Degoog Reddit extension calls `www.reddit.com/search.rss` without OAuth. Reddit says unidentified Data API traffic may be blocked and requires a registered OAuth token for its published free API limits. SearXNG maintainers discussed disabling their Reddit scraper after blocked-IP reports and recommended searching Reddit through a web engine with `site:reddit.com`. [Degoog Reddit source](https://github.com/degoog-org/official-extensions/blob/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/reddit/request.js), [Reddit Data API policy](https://support.reddithelp.com/hc/en-us/articles/16160319875092-Reddit-Data-API-Wiki), [SearXNG issue](https://github.com/searxng/searxng/issues/3444) | Strong explanation for the observed 429. Disable the Reddit RSS engine as a default; use web-index discovery for occasional posts or an approved OAuth-based source when native Reddit coverage is needed. Changing User-Agent alone does not make RSS an authenticated API. |
| DuckDuckGo returns zero | Degoog's extension fetches `html.duckduckgo.com` and parses HTML. In its current code, a successfully fetched page with zero parsed results is returned as an empty result array; Degoog then labels that run `ok` and can cache it for the normal TTL. A recent SearXNG issue reproduced CAPTCHA for the `wt-wt`/“all” locale while other locales worked. [Degoog DDG engine](https://github.com/degoog-org/official-extensions/blob/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/duckduckgo/index.js), [Degoog cache](https://github.com/degoog-org/degoog/blob/5cd67cec74d38944792db498b604790624a1cbbe/src/server/search/engine-cache.ts), [SearXNG locale issue](https://github.com/searxng/searxng/issues/6779) | Likely avenues, not a diagnosed cause of our exact five successes. Inspect status and returned body in a low-volume canary; compare explicit `en-US` or relevant locale with `all`, and fresh vs cached results. Do not simply loop retries on a challenge. |
| Bing returns generic pages despite `site:` | The Degoog Bing engine forwards the query to Bing's ordinary web page and parses its organic cards. Degoog's merger scores position and cross-engine agreement; an engine's Score multiplier and domain scoring can demote junk **after retrieval**, but cannot force Bing to execute `site:` as intended. SearXNG users have separately reported Bing irrelevance. [Bing request](https://github.com/degoog-org/official-extensions/blob/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/bing/request.js), [scoring code](https://github.com/degoog-org/degoog/blob/5cd67cec74d38944792db498b604790624a1cbbe/src/server/search/scoring.ts), [Degoog ranking controls](https://degoog-org.github.io/docs/tips-and-tricks.html), [SearXNG discussion](https://github.com/searxng/searxng/discussions/5651) | Strong on mechanism, weak on why Bing produced each particular URL. Lower Bing's default score, use it only as a fallback, and route strict site searches to an engine that passes the site probe. Count expected-domain URLs, not merely nonempty results. |
| Startpage intermittently empty or unparseable | Degoog's extension distinguishes CAPTCHA, suspended IP, interstitial and parser errors, so check `engineTimings` rather than grouping these as empty. Its maintainer advised updating the extension for a past parser break; another reporter saw Startpage work when a VPN was off. The docs suggest a browser/FlareSolverr transport for challenged Startpage traffic. [Startpage engine](https://github.com/degoog-org/official-extensions/blob/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/startpage/index.js), [issue and maintainer replies](https://github.com/degoog-org/degoog/issues/239), [Degoog transport guide](https://degoog-org.github.io/docs/tips-and-tricks.html) | A clean zero-result `ok` is different from a blocked or unparseable page. First verify the extension version and a fresh, low-volume canary. Escalate transport only if the status supports it. |

Degoog's [API](https://degoog-org.github.io/docs/api.html) exposes per-engine result counts, timings, status, and request-level engine selection. Its cache stores normal runs for **12 hours** by default and error runs for **two minutes**; an `ok` zero-result parse gets the longer duration. Clear only search cache when verifying an engine change, or use the documented single-engine retry that bypasses its cached run. [Cache defaults](https://github.com/degoog-org/degoog/blob/5cd67cec74d38944792db498b604790624a1cbbe/src/server/utils/cache/cache.ts), [retry behavior](https://degoog-org.github.io/docs/nojs.html), [cache controls](https://degoog-org.github.io/docs/server-settings.html)

## Narrow follow-up on this Mac

The disposable Degoog 1.1.0 instance was restarted to clear its in-memory cache,
then a few diagnostic queries were sent through the JSON API. Raw responses
are in ignored `build/search-index-eval/degoog-diagnostic-{fetch,curl}.json`.
These canaries explain specific misses; they are not a fresh 27-query eval.

| Change | Observation | Implication |
| --- | --- | --- |
| Keep Fetch; ask DuckDuckGo for the `SEARCH-056` site-scoped query after restart | Ten Reddit URLs, where the earlier long run had zero from DuckDuckGo for that case. A shorter wording also returned ten. | The earlier empty result was not a permanent lack of DDG coverage. Cache, upstream behavior, or query timing remain unisolated. |
| Keep Fetch; shorten the exact Startpage Amazon `site:amazon.com/dp` query | The exact query again returned zero with `status=ok`; a broad Amazon query returned ten results, led by Amazon `/clp/` pages rather than the requested `/dp/` product page. | Query relaxation can recover candidates, but not proof of an exact product listing. |
| Keep Fetch; remove the restrictive YouTube channel `site:` prefix from a Startpage query | The original `SEARCH-030` wording again returned zero; the broader query returned ten results led by YouTube watch URLs. | Try a broader discovery query, then verify channel and date on YouTube itself. |
| Switch DuckDuckGo and Startpage to the built-in Curl transport on this Mac | DuckDuckGo failed with `curl: (56) Unrecognized content encoding type`; Startpage failed with a repeated Anubis interstitial and a cookie-loss diagnostic. This Mac's `/usr/bin/curl` lists no Brotli support while the DDG engine advertises `br`. | Curl is not an improvement in this environment. The disposable settings were returned to Fetch. Test the binary and cookie handling before choosing Curl or Curl Fallback. [Curl transport implementation](https://github.com/degoog-org/degoog/blob/5cd67cec74d38944792db498b604790624a1cbbe/src/server/extensions/transports/builtins/curl/curl-fetch.ts), [DDG request headers](https://github.com/degoog-org/official-extensions/blob/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/duckduckgo/request.js) |

The official Google CSE extension worked over Fetch for one Reddit query
(20 results) and one GitHub query (six results), but the same exact Amazon
product-page probe returned zero. Its default `cx` is a **shared public
Programmable Search Engine**, whose coverage depends on that engine's
configuration. It is a possible no-key fallback for discovery, not evidence
that Degoog supplies full Google Search or fixes shopping. [Google CSE settings](https://github.com/degoog-org/official-extensions/blob/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/google-cse/settings.js)

## Transport choices and their actual evidence

Degoog lets an operator select an outgoing HTTP client per engine. In [its Brave 429 issue](https://github.com/degoog-org/degoog/issues/330), several users confirmed that switching **Brave HTML scraping** to `curl-impersonate` restored results, and the extension now names that as its default. This is a concrete success for Brave, not proof it fixes Reddit RSS, DDG, or Startpage. The binary must actually be installed: Degoog's [transport guide](https://degoog-org.github.io/docs/tips-and-tricks.html) says selecting it without the binary yields a network error. Degoog's official extension catalog also has a separate [Brave API Search engine](https://github.com/degoog-org/official-extensions/tree/5013f065ed879e188adc7b1cd1020f8b26e47bb8/engines/brave-api-search), which uses a key and avoids scraping Brave's HTML. That is the cleaner way to feed an already-provisioned Brave API into Degoog if unified output matters; it does not improve Degoog's own engine coverage by itself.

For more protected sites, Degoog documents FlareSolverr, Browserless, CloakBrowser, Camoufox, and 4play. Its maintainer says Google's scraped HTML needs a real Firefox session through 4play and suggests Google CSE as a simpler plain-HTTP option. [Official transport guide](https://degoog-org.github.io/docs/tips-and-tricks.html), [Google 403 issue](https://github.com/degoog-org/degoog/issues/247). These add processes, state, and maintenance; the 4play instructions currently have an [open documentation bug](https://github.com/degoog-org/degoog/issues/337). They are poor defaults for this project's preference to avoid operating extra infrastructure. Treat CAPTCHA as a stop/cooldown or manual session-repair signal, not something to solve automatically in eval traffic.

SearXNG offers similar engine-specific controls: weights, timeout, proxy assignment, and retries on chosen HTTP codes. It suspends engines after upstream 429 by default rather than continually retrying them; its own inbound limiter requires Valkey and protects origin engines from bot traffic. [Engine settings](https://docs.searxng.org/admin/settings/settings_engines.html), [outgoing settings](https://docs.searxng.org/admin/settings/settings_outgoing.html), [suspension defaults](https://docs.searxng.org/admin/settings/settings_search.html), [limiter](https://docs.searxng.org/admin/searx.limiter.html). A 429 **from the SearXNG endpoint** may instead be its inbound limiter, particularly behind a misconfigured reverse proxy; inspect which hop emitted it before tuning upstream engines. [Maintainer answer](https://github.com/searxng/searxng/discussions/4265)

4get is another scraper-based alternative, not a managed index. Its [public API terms](https://git.lolcat.ca/lolcat/4get/src/branch/master/api.txt) expressly disallow intensive scraping and activity not triggered by a human on the author's instance, and ask callers to cache responses; some instances require a CAPTCHA-earned pass. That is a poor fit for unattended agent eval traffic on public instances. Self-hosting would move the same upstream-blocking problem to our own IP and add an operator burden. A [community SearXNG/4get bridge](https://github.com/cra88y/4get-hijacked) uses `curl-impersonate` and proxy hooks, but its own README warns that its Google engine currently needs a residential proxy in some deployments. Treat this as a brittle experiment, not a reliable remedy.

## Engine repair and access trial on 13 October 2026

The same disposable loopback instance was used for fresh single-engine platform probes. Its data and binary remain under ignored `build/search-index-eval/`; raw response rows are `degoog-{duckduckgo,startpage}-fresh-platform.jsonl`, `degoog-brave-{impersonate,api}-platform.jsonl`, `degoog-brave-api-core.jsonl`, and `degoog-startpage-brave-api-{core,platform}.jsonl`. The result counts below mean that at least one top-ten URL had the requested source domain and path. They do **not** establish that a listing is current, a video answers the question, or an Alibaba page names a supplier and MOQ.

| Engine or access route | Observed result | Decision |
| --- | --- | --- |
| Reddit RSS | A Devland Reddit account was created and its login saved in 1Password. Reddit acknowledged a truthful request for personal, read-only OAuth Data API access; no OAuth client or key has been issued. [Reddit's current policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy) requires explicit approval, and [its October 8 notice](https://support.reddithelp.com/hc/en-us/articles/54353370049684-Changelog-October-8-2026) says RSS support ends November 13, 2026. | Do not use the RSS engine as the Reddit integration. An OAuth adapter cannot be tested until approval and a client exist. |
| DuckDuckGo HTML | Fresh requests found source URLs in 2/9 platform probes. Then a direct response was HTTP 202 with DuckDuckGo's human-verification page. The stock engine parsed it as `status=ok`, zero results. A local, ignored copy now raises Degoog's `captcha` engine error for HTTP 202 or the challenge markup; a fresh retry confirmed `status=captcha`. `curl-impersonate` did not clear the challenge. | The local patch fixes the false `ok` classification and shorter error caching, not DDG access. Exclude it from unattended default fan-out while challenged. Do not solve the CAPTCHA in eval traffic. |
| Bing HTML | Fresh strict GitHub probes returned generic Microsoft, Craigslist, or unrelated pages despite the query containing `site:github.com`. Switching this engine to `curl-impersonate` still returned ten generic results and zero requested GitHub issue URLs. Another Reddit `site:` probe did return Reddit URLs, so the failure is query-dependent. | Treat `ok` and ten results as insufficient. Do not let Bing fill strict source queries without validating destination domains and paths. |
| Startpage HTML | Fresh platform probes found the requested URL shape in 8/9 cases; the Amazon `/dp/` query remained `ok` with zero results. Removing the restrictive `site:` term returned product-looking Amazon `/clp/` URLs, but not a verified `/dp/` listing. `curl-impersonate` left the exact `/dp/` probe empty. | Use Startpage for free discovery, then broaden and verify or fall back to another source when a required URL shape is missing. Its empty result is not evidence of a transport block. |
| Brave HTML via `curl-impersonate` | Degoog's own isolated installer supplied the macOS ARM64 binary. The first three platform probes returned requested Reddit, HN, and YouTube URLs. The next six returned upstream HTTP 429. | This transport works for a short burst but is not a reliable unattended replacement for the API from this IP. Stop on 429. |
| Brave **API** extension | The existing Devland key worked in Degoog's official API extension. It returned at least one URL in 26/27 core cases and the requested source URL shape in 9/9 platform probes. `SEARCH-028`, a narrow GitHub issue query, still returned zero. [Brave's published Search API price](https://brave.com/search/api/) is $5/1,000 requests with $5 monthly credits. | Use as the paid fallback to Startpage, or as the single Degoog web engine when reliability matters. Keep native GitHub search for repo/code/issue precision. |

The measured **default Degoog bundle** enabled only Startpage and Brave API for web search. Its JSON endpoint reported exactly those two engines for a smoke query, returned at least one URL for 26/27 frozen core cases, and found the requested source URL shape in 9/9 platform probes. Both engines missed `SEARCH-028`, a narrow GitHub issue query. Degoog's `disabled` extension setting did **not** change API default selection: the working selection was written through `POST /api/settings/default-engines`. This bundle sends every query to the paid Brave API, even when Startpage succeeds.

For lower cost, an agent can query Startpage first and call Brave API only when Startpage is empty or misses a required source domain/path. An offline replay of the separately run platform probes gives 9/9 source URL shapes with one Brave API fallback for the Amazon case; that routing rule was **not** deployed or timed end to end. Avoid DDG while its challenge persists, Bing for strict source queries, and Reddit RSS. The local diagnostic CAPTCHA patch and default-engine selection live only in ignored scratch state. The server was stopped after the trial, and the copied Brave key was removed from its data directory; the key remains in Devland 1Password. No permanent search service, proxy, or Reddit OAuth adapter was deployed.
