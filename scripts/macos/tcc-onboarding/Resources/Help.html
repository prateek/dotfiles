Review your app permissions

Dotfiles Permissions compares the permissions in your inventory with macOS records. You make every change in System Settings.

Allow permission checks

The helper needs Full Disk Access to read macOS permission records. Open Privacy & Security → Full Disk Access, add the helper, and enable it. Relaunch the helper if the records remain unreadable. macOS grants broad disk access; this helper uses it to read permission records and never changes them.

Review one permission at a time

The compact window groups apps by permission, so you can work through one Settings pane before moving on. Select a row to expand its purpose, recorded status, and next steps. More → View also offers By app, Drag shelf, larger text, All permissions, and an optional menu bar icon.

Use More → Keep above Settings to keep this window beside Settings. Permission records recheck automatically while the window is open. For a manual check, use More → Recheck permissions or ⌘R. Evidence includes the exact subject and last-check time. Closing the window preserves your review; use the Dock, View → Open, or the optional menu bar icon to return.

Later leaves access unchanged and defers a task for this session. If every remaining task is deferred, use Resume. A newly matching task stays visible until you choose Next or Summary.

Add the exact app

For Accessibility, Input Monitoring, and Full Disk Access, drag the entire file tile into the permission list and enable the entry. File Details… offers Show in Finder, Copy Path, and exact-path keyboard help; where Settings provides an add (+) button, use it, press ⌘⇧G in the file chooser, and paste that path. A declared helper executable may differ from the enclosing app bundle.

Microphone, Camera, and Screen Recording access must be requested by the target app. Open the app and use the relevant feature. For a recorded denial or changed identity, review Settings first. No drag instruction is offered for app-request services.

Understand the status

  • Recorded allow: the recorded grant matches the installed code. An app may need to restart before adopting changes.
  • Not allowed: macOS records a denial.
  • Identity changed: the saved permission does not match this installed copy. Follow the visible removal and re-add instructions where the service permits.
  • Needs a grant: no recorded decision exists for this exact subject and permission.
  • Cannot check: evidence is unreadable, conflicting, unsupported, ambiguous, or unverifiable. Check Evidence and the existing Settings entry before deciding whether to change access.
  • Not installed: no matching app or declared helper exists; no grant is requested.

Recorded state does not prove an app’s features work. The helper never resets permissions or automates Settings switches. Later leaves access unchanged.
