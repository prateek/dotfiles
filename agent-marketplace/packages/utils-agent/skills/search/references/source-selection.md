# Choose sources for the evidence

Read this when choosing search branches, exploring a broad request, or deciding
where to look after weak results. Prepared consumers supply their own query policy.

## Vocabulary

| Term | Meaning |
| --- | --- |
| Area | Evidence policy: web, code, social or shopping |
| Source | Publisher, community, platform or scoped site containing evidence |
| Source family | Useful planning group, such as official documentation or local auctions |
| Provider | Executable retrieval service, such as Exa or HN Algolia |
| Upstream | Known index/data provenance; unknown stays unknown |
| Method | API, native CLI, host tool or browser |
| Operation | Discovery, inspection or a qualified native read |

A provider may reach many sources. A source may serve several areas. A catalogue
entry says where evidence might live; capabilities say which operations can run.
Configuration, observed access and answer coverage are separate facts.

## 1. Establish material context

Use the request, conversation and available deliberately saved context. Record
whether each material fact is explicit, conversational, saved or assumed. Infer
reversible low-impact defaults; ask a focused question when an unknown changes
feasibility or the recommendation. Continue independent work while waiting.

Consider purpose, recency, audience and language. For buying, also consider market,
currency, quantity, condition, compatibility, delivery deadline, pickup/import
tolerance and warranty. Gather only what changes the search. Nationality does not
establish language or delivery market. Keep private addresses in an authorized
session. Finish with requirements, binding restrictions and named material unknowns.

## 2. Choose complementary branches

Read the relevant area guides. Start with primary evidence, relevant experience
or specialist evidence, and an alternative channel when it could change the answer.
This is a heuristic, not a three-source quota. Choose among:

| Breadth | Useful starting behavior |
| --- | --- |
| Focused | Exact entity/version or a selected destination; add corroboration when needed |
| Ordinary | A small complementary set covering the decision's main uncertainties |
| Wide | State relevant families, languages and markets; explain omitted major branches |

Source examples are seeds. Discover additional communities, sellers or official
portals through citations and native-language searches when the seeds fit poorly.
Missing credentials should leave a visible gap or useful alternative, rather than
change the question. Finish when each required claim has a facet or an explicit gap.

## 3. Resolve routes and reserve inspection

Use `capabilities` and the resolved plan. Native search fits its qualified
structured operations; keyword routes suit identifiers; semantic routes may help
conceptual discovery; inspection supplies evidence missing from indexes. These
are starting hypotheses, not universal rankings. Compare supported filters,
upstream independence, actual yield, cost and available time.

Record budgets before retrieval. Three discovery facets and two page inspections
need at least five calls, three discovery slots, two enrichment slots and two
opens; retries or provider fan-out need additional allowance. Request limits cap
fetched rows, not calls or final recommendations. Use measured latency to size the
deadline. Wide breadth never raises engine limits automatically.

Place agent-chosen starting sources on individual facets. Global `source`, `area`,
provider and method choices constrain the entire run, including later extensions.
“Start with Reddit” can be a Reddit facet; “only Reddit” needs a global restriction.
Finish when the plan can perform the selected checks within authorized limits.

## 4. Expand or stop

Use `extend` on the same state when a missing requirement, conflicting claim,
untranslated term or promising new source justifies another branch. Keep the
original deadline, reservations and authorization. Material changes to requirements
need explicit scope handling and reassessment, not a silent intent rewrite.

Stop when inspected evidence supports the requirements, further plausible branches
would not change the answer, or access/budget prevents progress. Save a concise
`stopping_reason` with `select` and report material omissions. Duplicate indexes,
reposts, translations and syndicated articles do not independently corroborate a
claim. Source count is not the quality measure.

For international or non-default-language branches, read
[multilingual exploration](multilingual.md). For new site scopes, context records
or source decisions, read [source contracts](source-scopes.md). For changing the
skill itself, read [extension ownership](extending.md).
