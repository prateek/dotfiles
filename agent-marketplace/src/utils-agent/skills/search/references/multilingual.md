# Multilingual and regional exploration

Read this for non-default-language evidence, regional communities, cross-border
markets or an international comparison. Use the requested answer language even
when useful evidence is in another language.

1. Separate query language, observed content language, answer language and market.
   A Korean speaker in Canada may need Korean owner reports and Canadian offers.
   Finish with the relevant dimensions and the origin of each assumption.
2. Preserve exact entities, model numbers, versions, error messages and identifiers.
   Add native terminology, local product names, transliterations or script variants
   when useful. A literal translation may miss the community's vocabulary. Finish
   with a small purposeful query set, not every language crossed with every site.
3. Read [East Asian ecosystems](regions/east-asia.md) for Chinese, Japanese or Korean
   branches; read [regional discovery](regions/global-discovery.md) for other regions
   or an unfamiliar local ecosystem. Use these as starting points. A platform has
   a role and audience, not a universal foreign-language equivalent.
4. Submit original text with optional facet `query_language`. This metadata records
   the query; it does not make providers filter language. `filters.language` remains
   a programming-language filter for code. Use only language/locale controls actually
   exposed by a qualified route. Finish when transmitted queries preserve the entities.
5. Inspect the original content. Preserve its URL, author, date, relevant passage
   and observed language. Mark translated summaries and uncertainty about slang,
   negation, quantities or context. Ask for language-capable judgment when it could
   change the recommendation. Search results alone do not prove native-language fit.
6. Group translations and reposts as related evidence, while retaining separate URLs
   and attribution. Do not count them as independent corroboration. Finish with
   inspected support or explicit language/access gaps and a brief coverage statement.

Regional engines such as Naver, Baidu, Yahoo! Japan or Yandex may warrant exploration
through an available route when existing coverage is weak. Naming them does not
establish an adapter, independent index, current access or a better result. Preserve
the same budget across English and local-language branches.
